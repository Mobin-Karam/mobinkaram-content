دریافت داده همان جایی است که رابط کاربری با عدم قطعیت روبه‌رو می‌شود: درخواست می‌تواند در حال اجرا باشد، شکست بخورد، داده خالی برگرداند یا نتیجه مفید داشته باشد. این حالت‌ها را صریح کنید.

## مرز داده را type کنید

در لحظه ورود پاسخ به برنامه، شکل آن را تعریف کنید و `any` را در کامپوننت‌ها پخش نکنید.

```ts
type Article = { id: string; title: string; publishedAt: string };
```

برای API غیرقابل اعتماد همچنان به اعتبارسنجی runtime نیاز دارید؛ TypeScript فقط فرض‌های کد را بررسی می‌کند.

## پیش از محتوا، وضعیت را render کنید

```ts
type QueryState<T> =
  | { status: "loading" }
  | { status: "error"; message: string }
  | { status: "success"; data: T };
```

حالا هر شاخه داده مورد نیازش را دارد و view موفق نمی‌تواند ناخواسته پاسخ undefined بخواند. نتیجه خالی هم باید یک صفحه آگاهانه داشته باشد، نه ظاهری شبیه خطا.
