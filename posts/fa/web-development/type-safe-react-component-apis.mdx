API یک کامپوننت، قراردادی با کسانی است که از آن استفاده می‌کنند. TypeScript این قرارداد را کنار خود کامپوننت نگه می‌دارد، نه فقط در یک سند طراحی.

## از کمترین props مفید شروع کنید

فقط داده‌هایی را تعریف کنید که کامپوننت واقعاً نیاز دارد. وقتی گزینه‌ها مشخص‌اند، union محدود بهتر از `string` عمومی است.

```tsx
type ButtonProps = {
  tone?: "primary" | "quiet" | "danger";
  loading?: boolean;
  children: React.ReactNode;
};
```

این کار autocomplete بهتر می‌دهد و استفاده از حالت‌های پشتیبانی‌نشده را متوقف می‌کند.

## حالت‌های مرتبط را کنار هم مدل کنید

ترکیب چند boolean مثل `loading` و `error` معمولاً حالت‌های ناممکن ایجاد می‌کند. discriminated union اجازه می‌دهد وضعیت معتبر دقیقاً مشخص باشد.

```tsx
type SaveState =
  | { status: "idle" }
  | { status: "saving" }
  | { status: "failed"; message: string };
```

نوع خوب تزئین نیست؛ نیت را مستند می‌کند، خطا را زودتر می‌گیرد و refactor را امن‌تر می‌کند.
