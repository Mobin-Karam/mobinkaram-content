بخش زیادی از باگ‌های UI از حالت‌هایی می‌آیند که نباید هم‌زمان رخ دهند. یک dialog نمی‌تواند هم بسته و هم در حال ارسال باشد.

## حالت‌ها را نام‌گذاری کنید

ابتدا حالت‌های واقعی تجربه را بنویسید: ویرایش، ارسال، موفقیت و خطا. سپس داده لازم برای هر حالت را در همان type قرار دهید.

```ts
type Checkout =
  | { mode: "editing" }
  | { mode: "submitting" }
  | { mode: "success"; receiptId: string }
  | { mode: "failure"; reason: string };
```

## گذارها را آگاهانه کنید

رویدادهایی مثل `SUBMIT` و `RETRY` باید فقط بین حالت‌های معتبر حرکت کنند. حتی بدون کتابخانه state machine، این مدل review کد را دقیق‌تر می‌کند.

اگر mode برابر submitting است، `isBusy` را از آن مشتق کنید و boolean جداگانه نگه ندارید. منبع حقیقت کمتر یعنی باگ همگام‌سازی کمتر.
